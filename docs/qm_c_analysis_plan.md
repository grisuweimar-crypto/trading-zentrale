# QM-C2 — Analysis Plan & Freeze

QM-C2 extends QM-C1 without creating a parallel governance path. QM-C1 owns the versioned hypothesis identity; QM-C2 binds that exact hypothesis version to one immutable analysis-plan version before confirmatory work can be considered ready.

## Purpose

The analysis plan predeclares the material statistical choices that otherwise create post-hoc degrees of freedom:

- primary estimand
- primary metrics
- population definition
- universe requirement
- evaluation windows
- exclusion rules
- outcome definitions
- planned sensitivity analyses

Every plan has a stable `analysis_plan_id`, an explicit `analysis_plan_version`, and a semantic SHA-256 `analysis_plan_hash`.

## Required order for confirmation

A QM-C1 hypothesis being marked `FROZEN_FOR_CONFIRMATION` is **not sufficient** after QM-C2. The governed path is:

1. Register a QM-C1 `CONFIRMATION` hypothesis version.
2. Register an analysis-plan version bound to the exact hypothesis ID, version, hash, mode and universe requirement.
3. Freeze the analysis plan while the hypothesis is still `DRAFT`.
4. At plan freeze, bind the immutable execution context required by QM-A:
   - code/commit hash
   - config hash
   - dataset snapshot hash
   - universe ledger version
   - instrument master version
   - label definition hash
   - benchmark definition hash
   - environment/dependency fingerprint
   - evaluation cohort ID
   - temporal boundary
5. Freeze the corresponding QM-A analysis with the exact identity generated by QM-C2. This identity contains both `hypothesis_version_hash` and `analysis_plan_hash` plus every freeze-context field.
6. Freeze the QM-C1 hypothesis.
7. Call the QM-C2 confirmation-readiness gate. Only an exact match across QM-C2, QM-C1, QM-A and QM-B returns ready.

This order prevents a result from being inspected first and the analysis plan being written afterward.

## QM-B integration

QM-C2 reuses the QM-C1 QM-B gate. It does not reinterpret historical-universe evidence.

If a confirmation hypothesis requests `STRICT_ASOF_INVESTABLE`, the current QM-B closure state remains authoritative. While QM-B reports that strict promotion is blocked by external evidence, QM-C2 plan freeze fails closed. Observed-scanner-universe research does not falsely claim strict investability.

## Discovery

Discovery plans may move from `DRAFT` to `EXPLORATORY`. They cannot be frozen for confirmation in place. A confirmatory hypothesis/plan must be an explicit governed version rather than a relabelled exploratory object.

## Immutability

The registry is append-only and hash-chained. Registered plan versions are never overwritten. A changed estimand, metric, population, window, exclusion, outcome or sensitivity specification requires an explicit successor `analysis_plan_version`.

The freeze context is also immutable once frozen. Changing code, data snapshot, universe version, label definition, benchmark, environment, cohort or temporal boundary therefore requires a new governed version rather than an in-place edit.

## Confirmation readiness

`AnalysisPlanRegistry.validate_confirmation_ready(...)` verifies all of the following together:

- plan is a confirmation plan and is `FROZEN_FOR_CONFIRMATION`
- exact QM-C1 hypothesis binding still matches
- hypothesis is `FROZEN_FOR_CONFIRMATION`
- QM-B strict-universe rules still pass
- QM-A points to the same governed analysis and is `FROZEN_FOR_CONFIRMATION`
- every immutable QM-A identity field equals the identity produced from the frozen QM-C2 plan

A direct QM-C1 hypothesis freeze without a matching pre-frozen QM-C2 plan is therefore not confirmation-ready.

## Boundaries

QM-C2 does not implement multiplicity, sequential monitoring or the final negative-results registry. Those remain QM-C3 and QM-C4 work. QM-C2 does not change scanner scores, Selection, Timing, Probability, Risk, Confidence, Elliott, Decision Layer, portfolio actions or execution.
